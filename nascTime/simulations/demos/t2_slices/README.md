# t2_slices —— 三流三切片（测试方案用例 T2）

> 对应《6G确定性承载网集成测试方案》4.6 节用例 T2。

## 拓扑

```
client1（切片1 / 高优先 1024 B / PCP 5） ┐
client2（切片2 / 中优先 1472 B / PCP 4） ┼─ pe1 ── pe2 ── server
client3（切片3 / 低优先  512 B / PCP 0） ┘
```

## 探针与因果定位（本轮核心结论）

### 探针方法

直接读 PE 出口各队列计数：

```
pe1.eth[3].macLayer.queue.queue[i].incomingPackets:count
```

### 三个配置错误（已修复）

| # | 真因 | 探针表现 | 修复 |
|---|---|---|---|
| 1 | 客户端未开流编码（`hasOutgoingStreams` 被删） | 7364 个包**全部**进 queue[0] | 补回流编码配置 |
| 2 | 默认映射表把 PCP4/PCP5 撞到同一类（IEEE 802.1Q 表8-5，3 等级时都→等级1） | 补回编码后 queue[2] 仍为 0 | 显式 `classifier.mapping` |
| 3 | 中间交换机剥掉 802.1Q 标签 | 分流正确、报文发出，但对端收不到 | 只在最后一跳 pe2 剥标签 |

修复后队列分流（1 s）：queue[2]=2052（切片1）、queue[1]=3519（切片2）、queue[0]=1793（切片3）。

### 门控窗口积压的因果实验

现象：TAS 下切片1/3 出现数十至数百毫秒积压。提出两个假设并逐一验证：

| 实验 | 条件 | HP 均值 | HP 最大 | 结论 |
|---|---|---|---|---|
| 基准 | 双交换机门控，HP 窗口 250 µs | 35.97 ms | 71.24 ms | — |
| **只开 pe1 门控** | 消除级联 | 35.59 ms | 70.86 ms | 与基准相同 |
| **只开 pe2 门控** | 消除级联 | 35.97 ms | 71.24 ms | 与基准相同 |
| **单流（仅 HP）** | 排除竞争，分类已验证进 queue[2] | 35.97 ms | 71.24 ms | 单流也积压 |
| **窗口放大到 400 µs** | 加大余量 | **0.574 ms** | 0.946 ms | 恢复 |
| **窗口 250 µs + 关闭保护带** | 验证保护带影响 | **0.631 ms** | 1.009 ms | 恢复 |

**结论**：

1. **不是级联相位问题**——只开单台交换机、甚至只跑单条流，积压依旧；
2. **是窗口余量问题**——放大窗口或关闭保护带即可消除。

### 机理

`PeriodicGate` 默认开启隐式保护带（`enableImplicitGuardBand = true`）：
报文若不能在窗口关闭前发送完毕，就不允许开始发送。因此**有效窗口 = 窗口长度 − 一帧发送时间**。

以切片1 为例：1024 B 载荷约 1050 B 帧，在 100 Mbps 下需 84 µs；窗口 250 µs，实际可用约 166 µs；
而 18% 负载每周期需要约 186 µs —— **需求大于有效窗口，队列持续积压**，若干周期后累积到数十毫秒。

### 窗口分配公式

```
窗口 ≥ 每周期该切片的发送时间 + 一帧发送时间（保护带）
每周期发送时间 = 负载比例 × 周期
```

按此重算（周期 1 ms、100 Mbps）：

| 切片 | 负载 | 每周期发送 | 单帧时间 | 最小窗口 |
|---|---|---|---|---|
| 切片1 | 18% | 180 µs | 84 µs | **264 µs** |
| 切片2 | 45% | 450 µs | 122 µs | **572 µs** |
| 切片3 | 8% | 80 µs | 42 µs | **122 µs** |
| 合计 | 71% | 710 µs | — | 958 µs（可行，余量很小） |

## 当前可用配置与结果

### 2 等级验证（HP 独占 0–300 µs，其余共享 300–1000 µs）

| 切片 | 接收 | 均值 | 最小 | 最大 |
|---|---|---|---|---|
| 切片1（HP，窗口 300 µs） | 4212 | **461 µs** | 260 µs | 791 µs |
| 切片2（共享窗口） | 5849 | 185.8 ms | 620 µs | 371 ms |
| 切片3（共享窗口） | 2980 | 185.7 ms | 406 µs | 371 ms |

HP 达到确定性目标（均值 461 µs、最大 791 µs），但共享窗口仍不够（两个切片合计需求 530 µs，
有效窗口 700−122=578 µs，利用率 92%，接近饱和后排队发散）。

### 3 等级尚未跑通的原因

`PeriodicGate` 的 `durations` **必须成对出现**，无法直接表达“闭 300 µs–开 580 µs–闭 120 µs”这种
三段窗口；中间等级的窗口需要用 `offset` 或 `GateControlList` 实现，当前未打通。这是纯配置限制，
与机制无关。

## 排查踩坑记录

1. **表达式分类器遇非 UDP 报文崩溃**：`expr(udp.destPort == N)` 对 ARP 与 IP 分片都会抛
   `Object nullptr has no member named 'destPort'`。对策：`**.arp.typename="GlobalArp"` + UDP 载荷 ≤1472 B。
2. **`GateControlList` 三相窗口不生效**：改用 `PeriodicGate`。
3. **探针优先**：看 `queue[i].incomingPackets:count` 比猜配置快得多，一轮就能区分“没打标 / 打错类 / 标签被剥”。
