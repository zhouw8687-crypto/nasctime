# 三分支实验复核与双 UE 跨域闭环补充

2026-11-27。研究问题是在两个 UE 竞争同一基站、左侧承载路径同时过载时，无线调度、GCC 的观测对象和上报码如何共同影响端到端交付。业务方向为下行，统计按发包时刻归组。

## 原实验分别证明了什么

| 分支 | 核对的证据与结果 | 能支撑的结论 |
| --- | --- | --- |
| 双 UE 瓶颈 | 原 45 次运行。仅左链路拥塞时，视频在 5 个种子均为 0.448 Mbit/s，固定绕行后为 2.000。仅无线竞争时，MAXCI 在种子 1、2 把整个突发窗的 4000 个块都给 UE1，UE0 的控制按期数为 0/100。90 个配对抓包散列均一致。 | 分离了无线与承载扰动。调高小区频带上限无法保证受测 UE 获得授权。核心未施加独立扰动。 |
| 域自治与全信息 GCC | 单 UE、种子 0、两种控制器各 4 组，448 轮观测/命令/回读重新通过验证。低发送量、高目标时两种策略均交付 47/48 个视频包。GCC 使用直达和 4 频带，独立决策使用绕行和 10 频带。两组累计实际调度块同为 864。 | 能根据其他域的信息减少多余的预算和绕行。全信息指求解器可以看到其建模的全部变量；服务率和时延仍由代理模型估计。 |
| 控制消息 | 核对 2 条单 UE 轨迹，各 56 点。全量为 22,800 bit/s，阈值定点为 4,757 和 4,857 bit/s，分别节约 79.1% 和 78.7%。两条轨迹各出现一次候选分歧。 | 说明旧规则在固定轨迹上的码率与分歧。原回放不会因提前选路而改变后面的队列或 UE 收包。 |

## 共同参数与判定

日字形承载网中，UE0 业务经 UPF、承载网和 gNB 下行，控制流 200 B/5 ms，视频流 1000 B/4 ms；两者共享一条 N3 路径。UE1 的无线竞争在 gNB 本地注入，1200 B/0.4 ms。左侧 10 Mbit/s 链路的独立背景负载为 16 Mbit/s。两项扰动均在 [400,900) ms 生效。UE0 在突发窗发送 100 个控制包和 125 个视频包，UE1 发送 1250 个竞争包。全程 4 s 含排空时间。控制实验阈值为 20 ms 内交付至少 99/100，视频吞吐按该发送窗口内最终交付的应用净荷计算。全矩阵使用相同的种子 0–4 逐对比较。

## 补充一：用原生 PF 替换 MAXCI

把 Simu5G 的下行调度规则作为实验变量，原 9 个配置各跑 5 个种子。PF 是基站本地运行的比例公平调度；本组在仿真开始前选定调度规则。其余流量、路径、频带及测量窗口与原 MAXCI 矩阵相同。

| 固定 4 频带工况 | MAXCI 突发期 UE0 控制按期数，种子 0/1/2/3/4 | PF 的对应计数 | PF 视频吞吐 |
| --- | --- | --- | --- |
| 仅无线竞争 | 100 / 0 / 0 / 100 / 100 | 100 / 100 / 100 / 100 / 100 | 各 2.000 Mbit/s |
| 无线与承载同时竞争，直达 | 100 / 0 / 0 / 100 / 100 | 100 / 100 / 100 / 100 / 100 | 各 0.448 Mbit/s |
| 无线与承载同时竞争，绕行 | 100 / 0 / 0 / 100 / 100 | 100 / 100 / 100 / 100 / 100 | 各 2.000 Mbit/s |

仅无线竞争时，PF 在五个种子都给了 UE0 共 1200 个实际调度块，MAXCI 的对应数为 1184、0、0、1200、1200。PF 矩阵的 90 个承载抓包配对仍逐字节相同。由此可以定位两种收益：基站调度改善了关键 UE 获得服务的机会，承载绕行恢复了视频吞吐。五种子的结果只描述当前负载档和信道设置。

## 补充二：修正 GCC 读取的无线队列

原代码把整个小区所有 CID 的 MAC 虚拟缓冲区字节数相加，再代入受测控制流的排队时延公式。单 UE 时该选择不显眼，双 UE 时竞争者积压也进入 UE0 的时延预测。在双扰动、精确上报的对照中，两种调度规则的每个种子都出现 45/56 轮候选集为空，保持初始直达路径。即使 PF 已让控制包按期，视频仍只有 0.448 Mbit/s。

新配置按 UE0 的 NR MAC 节点标识筛选 CID，沿用相同的域预算、成本、候选动作、GCC 和控制周期。PF 五个种子均恢复至 0/56 轮空集，均在 440 ms 绕行、1020 ms 回切。控制均为 100/100 按期，视频均为 2.000 Mbit/s。MAXCI 种子 1、2 虽然也执行了换路，精确上报下仍各有 28 轮空集，控制仍为 0/100。这说明总预算、UE 自身积压和实际可获得的无线服务是三个不同的量。当前按 UE 汇总其所有业务队列，服务能力仍使用代理值，尚不能从预测可行推出业务必定按期。

另外修正了 GCC 的零速率链路处理。不可用端口报告 0 bit/s 时，原先计算串行化时延会除零；现在返回不可行候选，其余可用路径继续参与枚举。回归用例覆盖该输入。此处只验证了求解器输入边界。

## 补充三：把上报接入闭环并验证量化造成的动作差异

每 20 ms 在域侧整理本地状态，经过编码、序列化和解码，只有恢复出的动态状态交给同一 GCC 求解。状态包含 UE0 积压、两路队列和优先类积压、端口速率/可用性以及 UPF 输入估计。公共拓扑和业务模型预装在两端。动作通过既有 TCP 桥实际执行，对每轮回读、端侧包序号和结果重新计量。采用零上报传输时延，合计码率为三个域模拟上报帧的字节数（含每帧 12 B 头）除以 1.12 s。实际 TCP 观测信封、命令与回执均未计入该码率。

PF、双扰动、UE0 积压观测下的结果如下。五个种子的 UE0 指标均与表中一致。

| 上报方式 | 合计应用层上报 bit/s | 首次绕行 | 控制按期 | 突发期视频按期 / 最终交付 |
| --- | ---: | ---: | ---: | ---: |
| 周期精确 | 30,400 | 440 ms | 100/100 | 117/125，最终 125/125 |
| 周期定点，队列取最近的 8 包格点 | 28,000 | 420 ms | 100/100 | 124/125，最终 125/125 |
| 周期发送与判决边界一致的队列编码 | 28,000 | 440 ms | 100/100 | 117/125，最终 125/125 |
| 同一边界编码，按变化或 40 ms 刷新 | 14,707.14 | 440 ms | 100/100 | 117/125，最终 125/125 |

三个队列区间为 0–4、5–23、24 包及以上，与求解器的两条拥塞判定边界对应。比较两种周期定点方案，线上长度相同，消息表达改变了换路时刻。比较两种边界编码方案，解码结果对决策等效，按变化发送进一步降低码率。和周期精确相比，边界编码加触发节约约 51.6%。此前 79% 来自旧上报字段、100 ms 最长静默和另一套策略，两种百分比的分母不同。

**分歧与损失要分别衡量。** 最近格点把首次绕行提前 20 ms，在这次单向突发中反而让 7 个额外视频包按期；同期 UE1 最终交付从种子 0–2 的 843 包降至 840 包，从种子 3–4 的 829 包降至 824 包。选择与全信息动作不同，既可能改善某条业务，也可能引入另一条业务的代价。后续训练应保留分业务结果及可行性标签。

## A100 复现与原始证据

在 A100 的集成工作树运行，最后一个目录参数使用尚未存在的路径。固定 PF 的 45 次结果在 `/media/a100/data/zbw/review-pf-results-20261127`。全小区积压的首轮三种上报结果在 `/media/a100/data/zbw/review-live-20261127`，UE0 积压下最终四种上报的结果在 `/media/a100/data/zbw/review-live-four-20261127`。每次闭环运行保留 routes.jsonl、policy.jsonl、pcap 和向量；域内代码分别记录实际帧长度与执行回执。保留了三路历史提交和原始报告，全部新增开发在独立集成分支。

~~~bash
cd /media/a100/data/zbw/nasctime-review-20261127
d=/media/a100/data/zbw
sim="$d/simu5g17-qfi.nJ2rCJ/Simu5G-qos"
deps="$d/nasctime"
batch=$(mktemp -d "$d/review-repeat.XXXXXXXX")
DL_DISCIPLINE=PF bash experiments/exp/dual_ue/run.sh "$sim" "$deps" "$batch/pf"
for scope in cell ue0; do
    bash experiments/exp/integrated_review/run.sh "$sim" "$deps" "$batch/$scope" "$scope"
    (cd experiments/exp && python3 -B -m integrated_review.summarize "$batch/$scope") > "$batch/$scope/review.csv"
done
(cd experiments/exp && python3 -B -m unittest domain_coordination.test_baseline && python3 -B -m unittest discover -s control_reporting)
~~~

这批实验给后续语义压缩提供了两个可检验的约束。消息需要携带“哪个 UE / 哪条业务”的作用范围，统计量需保留当前策略真正使用的决策边界。仍需独立变化核心准入、测试扰动消退或误报，并注入控制链路延迟，才适合估计更广负载分布下的压缩收益与决策遗憾。
