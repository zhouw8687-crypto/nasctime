# 日字形三层路径规划与跨域联合优化

项目主问题是 **在端到端业务 SLA 和异构资源约束下，联合选择三层转发路径和分配各域资源**。原组会 PPT 第 5、6、8 页把路径求解交给承载域控制器，由 GCC 协调各域配额和全局目标。第 9、10 页的语义对齐与状态失配用于解释跨域控制信息如何表示、何时更新。先验证路径与资源决策，再验证压缩对决策的影响。

## 仿真边界

保留日字形六个 IP Router、双接入 UPF、两台 gNB 与 Simu5G 的 UE。分域的观测、策略下发及执行沿用现有外部 TCP 控制桥。承载域在可达图里计算有序下一跳和可行的队列配置。起步用可验证的显式 IP 路由实现路径动作，原生 SRv6 封装、信令和部署另行验收。Qbv 可作为承载端口的本地服务机制，在首批选路对照中固定其配置。

NW-TT/DS-TT 的用户面翻译器用于历史 5GS-TSN 桥接场景，FRER 及多流相位对齐独立验证。3GPP TS 23.501 §4.4.8.4 的逻辑 DetNet Router 架构允许省去 DS-TT 和用户面 NW-TT，同时为网络侧端口信息保留 NW-TT 控制面功能。仿真首版由已有域控制接口显式提供边界节点、可达性和端口能力，标准管理接口属于设备接入阶段。[3GPP TS 23.501 §4.4.8.2 和 §4.4.8.4](https://www.etsi.org/deliver/etsi_ts/123500_123599/123501/18.10.00_60/ts_123501v181000p.pdf) · [RFC 8939](https://www.rfc-editor.org/rfc/rfc8939.html)

## 优化变量和域间耦合

| 部件 | 域内输入 | 求解决策和对外输出 |
| --- | --- | --- |
| 无线域 MDC | UE 接入关系、无线负载、信道状态、配额 | 在当前服务小区求 RB 预算或调度动作；汇报可履约速率、时延代价及无线资源占用。 |
| 承载域 FDC | 拓扑、链路容量/队列、边界端点、时延和带宽预算 | 为相同边界端点生成候选 IP 路径；汇报每条路径的有序出口、剩余容量、时延估计与代价，执行被选路径。 |
| 核心域 CDC | UPF 可用出口、PDU Session、业务分类和资源约束 | 生成兼容的 UPF 出口和 QoS/限速动作；汇报所需承载边界、可用资源及代价。 |
| 全局 GCC | SLA、带时戳与版本的域候选、耦合约束 | 分配各域预算，选边界条件和相容候选，由各域执行并回报实际结果。 |

令承载域动作包含路径 P。全局解必须让核心网出口、路径起止边界和无线服务小区兼容，同时满足链路容量以及端到端 SLA。对异构资源分别设容量上限，或换算为有明确定义的归一化成本。只有在三个域的指标可以用相同单位表示时，才跨域直接相加。端到端 P99 以逐包端到端结果计算。

首轮冻结编码器与控制上报方式。先在满足最低按期送达率和带宽要求的组合中，比较端到端尾时延、按期吞吐和资源成本的 Pareto 前沿。用小拓扑完整枚举给出候选集内的参考前沿。分域协同用配额和边界节点生成本地可行解，GCC 对相容解做组合和筛选。固定资源预算或权重时，可从前沿选择一个动作并实际执行。

## 验证顺序

| 阶段 | 原理与目的 | 候选配置与对照 | 需要的证据 |
| --- | --- | --- | --- |
| L3-1 路径可控 | 固定相同业务、终端和服务小区，证明路径下发能改变实际下一跳。 | 固定 UE0/gNB1，分别使用 UPF→NE1→NE3→NE5、UPF→NE1→NE2→NE4→NE6→NE5 两条简单路径接 gNB1。两条路径复用相同的入口和终点，初版以静态显式路由或流策略实现。 | 下发路径、逐包实走节点/接口、终端送达。若规则作用在 N3 外层，记录外层匹配及覆盖业务范围；验证到内层流粒度前，按隧道粒度报告。 |
| L3-2 选路与域内分解 | 负载会改变路径的可行性和资源代价。验证 GCC 能用来自不同域的候选，选出符合端到端约束的组合。 | 将交叉背景流先施加在 NE3→NE5，两条候选在 NE5 汇合前经过不同链路。测无拥塞、局部拥塞和可绕行断链，按相同负载及种子比较固定最短路、负载感知约束路由、集中联合枚举、分域求解与 GCC 协同。 | 路径、每域动作和生效轨迹，逐包时延与违约率，按期吞吐，成本和到参考前沿的差距。资源和业务参数在首批对照中保持一致。 |
| L3-3 状态失配 | 验证状态过旧是否让 GCC 选到已经拥塞或失效的路径。 | 对照周期全量、阈值上报和强制新鲜度上限。单独注入确定的上报延迟、背景流阶跃或断链。 | 观测时间、接收时间、决策与生效时间，选路失败率、SLA 恢复时间和真实信令字节。 |
| L3-4 学习压缩 | 测试各域压缩后能否保持路由可行性及跨域决策质量。 | 比较完整候选、同位数量化、分别训练的域编解码器与跨域对齐。按负载、拓扑/故障和种子划分数据。 | 路径可行性误判、选路/前沿差距、执行后的 SLA、编码与解码尾延时、序列化位数。 |

首轮可以直接将无拥塞条件下每条路径的逐包结果存成可复现基线，再凭相同种子的负载或故障回放计算变化。L3-2 后续如果允许同一逻辑 UE 在两个小区间可达，才把服务 gNB 或会话迁移纳入联合决策。

A100 的 EXP-13 使用 server → UPF → NE1 → NE3 → NE5 → gNB1 → UE0 的固定路径，枚举 UPF 限速、NE1 门控和 gNB1 频带三类动作。它给出了控制下发与压缩对照的原型基线。当前待补的是路径进入搜索变量，并核实真实下一跳跟随策略变化。此文是研究与验证方案，表中新增实验尚待运行。
