# 端到端下行双流竞争实验

2026-11-23，在 A100 上运行四组。实验检查同小区、同承载出口的关键流是否受背景流阶跃影响，并区分缺口出现在承载段还是进入 gNB 之后。

## 设置与对照

使用 ProjectBookLadder 的既有 NR、UPF 和完整六网元拓扑。业务都走 server → UPF → NE1 → NE3 → NE5 → gNB1 → UE0。UE1 保留但无应用流。NE1–NE3 设为 10 Mbps，以在可重复的业务速率下形成共享承载瓶颈。其余 Ethernet 维持 100 Mbps，内部跨距设为 30 km。

| 项目 | 配置 |
|---|---|
| 控制流 | UDP 6200，净荷 200 B，每 5 ms 一包，DSCP 46 |
| 背景流 | UDP 6202，净荷 1000 B，DSCP 0。平时每 8 ms 一包，0.6–1.0 s 加压区间的目标间隔为 700 µs |
| 观察窗口 | 发送时刻 0.2–0.6、0.6–1.0、1.0–1.6 s。1.6 s 停发，运行至 3 s |
| FIFO | NE1 共享出口 384 包单队列。恒定背景组采用同样的 FIFO |
| 三队列常开 | 按外层 DSCP 分为三个队列，每队列 128 包 |
| Qbv | 保留分类与队列容量，只在 NE1.eth[1] 加 5 ms 周期门控，高/中/低窗为 600/100/4300 µs。中优无测试流 |

四组使用相同基站、UE、路由和随机种子。三组阶跃实验的流量完全相同。恒定背景对照用于判断异常是否与加压相关。FIFO 与三队列同为 384 包总容量，三队列做了容量分区。三队列常开和 Qbv 用来单独对照门控效果。

## A100 结果

按发送时刻落在 0.6–1.0 s 的报文分组，排空期间收到的报文仍记入这一组。表中 P99 只对已送达或已出队的样本计算。

| 配置 | 控制流到 UE 发/收 | 控制流端到端 P99 | 控制流 UPF N3 至 NE1 出口 P99 | 背景流到 UE 发/收 |
|---|---:|---:|---:|---:|
| CompetitionNoBurst | 80/80 | 7.210 ms | 1.123 ms | 50/50 |
| CompetitionFifo | 80/66 | 194.350 ms | 118.900 ms | 563/365 |
| CompetitionPriority | 80/69 | 87.600 ms | 1.105 ms | 563/342 |
| CompetitionTas | 80/69 | 87.000 ms | 0.242 ms | 563/278 |

- 两类流的包序号都能在 UPF N6、UPF N3、NE1.eth[1] 和通往 gNB1 的 NE5 PPP 口追踪。四组 gNB1 的 PPP 接收总数分别为 487、1000、990、880，与对应 PPP 抓包计数一致。gNB2 的 PPP 接收为 0。
- 加压期每组 80 个控制包均到达 gNB 侧路径，UE 端分别有 14、11、11 个未观察到。延长停止发包后的运行至 3 s，交付计数仍与 2 s 探索运行一致。缺口可定位到 gNB 入口之后，尚需 RLC/MAC 等观测进一步确认原因。
- 分队列已将控制流的承载侧等待压低。Qbv 又缩短该段时延，控制流端到端送达数与常开组相同。加压期背景流在 NE1 出口前未观察到的个数为 0、10、119。Qbv 全程低优队列记录 120 次溢出，其中一次对应稍后发送的报文。Qbv 组出队记录中，窗口外出队为 0。
- 以同一个控制包 160 为例，服务器在 900 ms 发送。FIFO 在 990.538 ms 完成 NE1 出口发送，UE 在 1094 ms 收到。三队列常开对应 900.615 ms 和 970 ms，Qbv 对应 900.252 ms 和 955 ms。首跳改善与无线侧仍有等待可同时观测。

## 复现与证据

在 A100 仓库根目录运行：

~~~bash
bash experiments/exp/run_ladder_competition.sh
~~~

每组输出 `flows.csv`、`packet-trace.csv`、五处 PCAP、原始 sca/vec 和日志。Qbv 组另有 `gates.csv`。追踪以 UDP 目的端口和 ApplicationPacket 序列号配对，纳秒值来自模拟器时间。NE1 与 NE5 的以太网观测点为帧发送或接收结束，NE5 到 UE 的差值含最后一段 PPP 及 gNB/UE 处理。空白阶段表示在本轮观测停止前未看到相应事件。

本轮原始数据归档位于 A100 的 `exports/e2e-competition-20261123.3fgDGE/competition-results.tar.gz`，同目录提供 SHA-256 文件。实验覆盖真实仿真数据路径上的静态机制对照，跨域策略下发和反馈控制仍属于后续验证。
