# EXP-05：T1 帧长矩阵（64 B ~ 9000 B）

> 对应《6G确定性承载网集成测试方案》3.2 节负载与帧长矩阵、4.5 节用例 T1。
> 场景：`nascTime/simulations/demos/pe_test/`（单流、2 跳、100 Mbps、NoGating）
> 脚本：`experiments/exp/t1_matrix.sh`

## 1. 测试方法

- 单条 UDP 流，帧长（载荷）取 64 / 128 / 512 / 1024 / 1472 / 9000 B，帧头统一 46 B（含 VLAN）；
- 负载按链路 100 Mbps 的比例计算，发送间隔 = （载荷 + 46）× 8 /（负载 × 100 Mbps）；
- 9000 B 巨帧需把接口 MTU 调到 9000 B（`*.eth[*].mtu = 9000B`）；
- 仿真 1 s，指标取接收端应用层的端到端时延与收发计数。

## 3. 四条结论

### 结论 1：时延由帧长决定，与负载无关

同一帧长在 30% 与 80% 负载下的均值完全相同（28.5 / 43.8 / 136.0 / 258.9 / 366.4 / 996.5 µs）。
说明单流无竞争时，时延就是**逐跳发送时间之和**，与到达率无关。

帧长从 64 B 到 9000 B，时延从 28.5 µs 涨到 996.5 µs，**增长 35 倍**，近似线性。

### 结论 2：抖动为零

所有组合的峰峰值与 RMS 都是 0。这是仿真中的理想结果：单流、固定间隔、无背景流量时，
队列永远不积压，时延是常量。真实设备会有硬件抖动（任务书要求单台设备 ≤5 µs），仿真无法体现。

**写报告时不能把“仿真抖动 0”等同于“设备抖动达标”**，必须在文中注明这是无干扰条件下的理论下界。

### 结论 3：小帧的带宽效率极低

| 帧长 | 帧效率（载荷/帧）| 80% 负载下的有效带宽 |
|---|---|---|
| 64 B | **58.2%** | 46.5 Mbps |
| 128 B | 73.6% | 60.2 Mbps |
| 512 B | 91.8% | 73.1 Mbps |
| 1024 B | 95.7% | 76.5 Mbps |
| 1472 B | 97.0% | 77.4 Mbps |
| 9000 B | **99.5%** | 79.5 Mbps |

同样标称 80% 负载，64 B 小帧实际只送出 46.5 Mbps 的有效载荷，9000 B 巨帧能送出 79.5 Mbps。
**小帧业务要按更高线速预留带宽**，否则有效带宽不达标。

### 结论 4：巨帧与门控（TAS）本质冲突

802.1Qbv 的保护带长度等于“一帧的发送时间”，在 1 ms 门控周期、100 Mbps 链路下：

| 帧长 | 保护带 | 占周期比例 |
|---|---|---|
| 64 B | 8.8 µs | 0.9% |
| 512 B | 44.6 µs | 4.5% |
| 1472 B | 121.4 µs | 12.1% |
| **9000 B** | **723.7 µs** | **72.4%** |

**9000 B 巨帧的保护带就吃掉 72% 的周期**，门控窗口几乎无处可放。这与 EXP-04 中
“切片1 窗口 250 µs、帧 84 µs 导致积压”的因果结论一致——只是巨帧把矛盾放大到不可用。

因此在实际配置中：**要门控，就不要用巨帧；要巨帧，就得靠帧抢占（802.1Qbu）把保护带降到
最小分片（约 127 B / 10 µs）**。

## 4. 对报告与后续的影响

1. 任务书“局域端到端 ≤4 ms”的指标，在小帧业务下更容易满足（时延低但带宽效率差），
   在巨帧下时延本身就接近 1 ms，留给门控与空口的余量很小；
2. 报指标时必须标注帧长，否则“时延 28.5 µs”这种结果没有可比性；
3. 帧长矩阵是 TAS 窗口分配的前置输入：窗口长度必须按**该切片实际帧长**计算保护带，
   不能用一个固定余量。
