# 04 · 已知问题与后续计划

> 按"能不能马上做"排序。每条都写了现象、复现方式、假设原因和建议动作。

---

## 1. 日字形承载网没有 Qbv（最关键的缺口）

### 现象
`e2e_ladder/` 的 NE1–NE6 是 `Router`（L3），没有 `Ieee8021qTimeAwareShaper`，
所以端到端场景里承载网**没有门控**。

### 原因
最初为了规避 L2 环路才把 NE 做成 Router。换成 `TsnSwitch` 会有两个问题：
1. L2 环路（日字形有 4 个环）；
2. gNB 的 N3 是 **PPP** 接口，PPP 不能直接接到 L2 交换机端口。

### 建议动作
1. 先把 NE 换成 `TsnSwitch`，**断开 `NE1–NE2` 和 `NE3–NE4` 中的任意一条**打破环路，验证 Qbv 生效；
2. 再补 RSTP（见第 2 条）；
3. gNB 的 PPP 与以太网之间加一个"网关"节点（Router 双侧接口），或把 gNB 的 N3 改成以太网接口。

## 2. L2 环路无生成树

### 现象
尝试在日字形上开 RSTP，报：

```
Unknown protocol: protocolId = 34, protocolName = ieee8022llc
at ...host.bl.in[2]
```

### 原因
BPDU 走 LLC（802.2），但端节点（TsnDevice）没有配置 LLC，收到 BPDU 直接崩溃。
即使全局设 `**.llc.typename` 也无法覆盖端节点。

### 备选方案
1. **断开环路**做成树（最简单，但拓扑不完整）；
2. 在端节点上补 LLC/STP 模块（需要改 NED，风险中等）；
3. 换成三层承载（NE 用 Router + 等价多路径），但就失去 Qbv；
4. 用 MRP（802.1Q 的介质冗余）代替 RSTP——INET 未必支持，需先查。

## 3. DSCP → PCP 映射缺失

### 现象
gNB 已经能把 5G 切片打成外层 DSCP（见 `exp-07`），但 L2 交换机的分类器
（`PcpTrafficClassClassifier`）读的是 **PCP**，不是 DSCP。所以 DSCP 进了承载网也没人用。

### 原因
INET 的队列分类器只识别 PCP（`PcpReq`/`PcpInd` 标签），没有 DSCP 版的 `IPacketClassifier`。
`MultiFieldClassifier` 支持 `dscp` 属性，但它不是队列分类器接口，挂不到 shaper 上。

### 建议动作
在承载网入口（PE 的 ingress 或 egress）加一个 `DscpToPcpMarker`：

```
读 IPv4 头的 DSCP → 查表 → 设 PcpReq 标签
```

可以照 `GtpUser` 补丁的写法做成 nascTime 库里的 `simple` 模块，约 50 行。
映射表参考：

| DSCP | PCP | 用途 |
|---|---|---|
| 46 (EF) | 5 | 语音/控制 |
| 34 (AF41) | 4 | 视频/大带宽 |
| 0 (BE) | 0 | 尽力而为 |

## 4. 帧抢占（802.1Qbu）未验证

### 当前结论（待验证）
"要门控就不要用巨帧；要巨帧必须上帧抢占" —— 目前是**推算 + 间接证据**
（9000 B 保护带占 1 ms 周期的 72.4%），没有直接做过抢占对照。

### 验证计划
1. 在 TAS 场景里把帧长改成 9000 B，窗口按公式放大，确认窗口需求接近 724 µs；
2. 开 `TsnSwitch.hasFramePreemption = true`（参照 `inet/showcases/tsn/framepreemption`）；
3. 对比开关抢占前后的大帧时延上界。

### 注意
源码里 `hasFramePreemption=true` 时会把 TAS 队列置空（`queue.typename = ""`），
**"门控 + 抢占"不能简单叠加**，必须照官方示例单独配。

相关模块：`EthernetPreemptingMacLayer`、`PreemptingServer`、`PreemptableStreamer`、
`EthernetFragmentingMacLayer`。

## 5. CQF（802.1Qch）INET 4.6 不支持

### 现象
INET 4.6 的 shaper 只实现 TAS / CBS(802.1Qav) / ATS(802.1Qcr) / PSFP(802.1Qci)，
**没有 Qch 循环队列转发**。

### 影响
测试方案里 CQF 的理论关系 `MaxDelay = φ + (SW+1)·T + ξ`、抖动 ≤ 2T 无法直接验证。
`pe_test` 里那几组 `CQF*` 配置其实是**用双队列反相门控近似**，不是真 CQF。

### 备选方案
- 移植 **CyclicSim**（TUM，`github.com/tum-esi/CyclicSim`，OMNeT++ + INET 4.4 fork，实现 CQF/CSQF/MCQF）；
- 或自己实现循环队列模块。

## 6. 仿真结果不能当设备验收依据

### 事实
- 仿真里单流无竞争时抖动恒为 0，这是**理论下界**；
- 任务书要求"单台设备抖动 ≤5 µs"，必须硬件实测；
- 没有仪表标定，所有结果只能算趋势级。

### 写报告的措辞
> "仿真环境下抖动为 0，为无干扰条件下的理论下界，设备级抖动需硬件实测确认。"

## 7. 接入侧整形（per-slice 令牌桶）未做

### 背景
`t2_ladder` 证明：多个切片共用接入链路时，单 FIFO 会破坏隔离；
给接入节点加优先级队列能恢复（318 ms → 814 µs）。但这是"优先级"，不是"限速"。

### 建议动作
在接入节点出口加 per-slice 令牌桶（对应真实 CPE/DS-TT 的做法），
把每个切片限速到其承诺速率，防止单切片饿死其它切片。

## 8. Simu5G 没有 5QI 概念

### 现状
Simu5G 用 **DSCP 直接当 QFI**（`TrafficFlowFilter.cc:139`，源码注释自认是简化）：

```cpp
// Simplified QFI derivation: use IP DSCP as QFI directly.
// In a real 5G UPF, this would be done via PDR/QER rules.
Qfi qfi = Qfi(ipv4Header->getDscp());
```

而 3GPP 的完整链路是四层：**5QI → QFI → DRB（SDAP）** 和 **QFI → 外层 DSCP**。

### 影响
- 5QI 的语义（GBR/MBR/时延预算）无法表达；
- 只能用 DSCP 值区分切片。

### 建议
若后续要精确建模，可以：
1. 在 UE 应用里用 DSCP 承载 5QI 值（0–63 够用）；
2. 用 `NrSdap.drbConfig`（JSON）显式配置 QFI→DRB；
3. 用本轮的 `qfiDscpMap` 配置 QFI→DSCP。

## 10. 后续路线（建议顺序）

1. **打通承载网 Qbv**：`e2e_ladder` 的 NE 换 `TsnSwitch`（先断环）
2. **DSCP→PCP 映射模块**：让 5G 的 DSCP 能驱动承载网队列
3. **接入侧 per-slice 令牌桶**：补齐隔离的最后一环
4. **帧抢占验证**：决定巨帧能不能用
5. **RSTP 或改无环拓扑**：让日字形真正可用
6. **CQF 移植**（可选，工作量最大）
